# Spots Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Load a whole heads-up preflop situation (two ranges, pot, stack, rake, line) into the Setup from a "Spots" tab, keep its line visible, and remember it in saved solutions.

**Architecture:** A pure `spot.ts` module (types, validation, modified test, line text) under a third IndexedDB store `spots` shown as a third explorer tab. The app store holds the loaded spot (`store.spot`) and the spot of the solution in memory (`store.solvedSpot`); tree loading and the tree "modified" mark skip the four spot-owned fields while a spot is loaded. The solution's spot rides in `tree_config.spot` (no Rust change). The spot pack is generated in the private `poker-ranges` repo.

**Tech Stack:** Vue 3 + Pinia + TypeScript, Dexie (IndexedDB), vitest; Node (poker-ranges tools).

**Spec:** `docs/superpowers/specs/2026-11-20-spots-design.md`

## Global Constraints

- English UI, GTO Wizard naming; existing components (`UiButton`, `UiMenu`, explorer rows and tags, `ask` from `library.ts`).
- Amounts in app units (tenths of a big blind); the reminder shows big blinds (`280` → `28bb`).
- The spot owns `startingPot`, `effectiveStack`, `rakePercent`, `rakeCap` (exported as `SPOT_FIELDS`).
- No GTO Wizard-derived data in this repo (code, tests, fixtures): tests use made-up ranges such as `"AA,KK"`.
- Saved trees without a loaded spot behave exactly as today.
- Commits without any Co-Authored-By line; one branch `feat/spots` from `dev`, one PR to `dev`.
- Local checks before pushing: `pnpm vitest run`, `pnpm vue-tsc --noEmit -p tsconfig.json`, `pnpm eslint src`, `pnpm prettier --check src` (in `desktop/`).

## Review Focus

1. A spot whose second range fails to parse: nothing of the Setup changes (ranges, pot, stack all as before) and the explorer shows the error.
2. Loading a spot while the tree lines editor is open: the same Save/Discard/Stay guard as loading a tree runs first (`leaveTreeEdit(undefined, "load")`).
3. Typing the pot back to the spot's value after editing it: the reminder is no longer "modified" (pot/stack/rake are compared, not latched); a range edit stays latched until the spot is reloaded.
4. Deleting or renaming the loaded spot in the explorer: the reminder keeps working (rename follows the path; delete keeps the values and the reminder, the explorer tag disappears).
5. Importing a spots file into the Ranges tab (or the reverse): refused with "Data type mismatch", as today.

### Task 7: The spot pack generator (repo `poker-ranges`, not this repo)

**Files (in `C:/Users/micam/perso/projects/poker-ranges`):**
- Modify: `tools/gtow-pack.mjs` → also writes `packs/nl10-100bb-cold-calls.spots.json` (`{version: 2, name: "spots", data}`)
- Create: `tools/spot-math.mjs` — `potAndStack(line)` (pure) and its test `tools/spot-math.test.mjs` (`node --test`)
- Modify: `README.md`

Spots (heads-up, everyone else folds), in folders `Single raised pots`, `3-bet pots`, `4-bet pots`, `Squeeze pots`, then the opener's position (4 levels max):

| Line | OOP/IP ranges |
|---|---|
| X open, Y call | X `raise` of `RFI - X open`; Y `call` of `vs RFI - Y vs X open` |
| X open, Y 3-bet, X call | Y's `raise` from vs RFI; X's `call` of `vs 3-bet - X open vs Y 3-bet` |
| X open, Y 3-bet, X 4-bet, Y call | X's `raise` of vs 3-bet; Y's `call` of `vs 4-bet - Y 3-bet vs X 4-bet` |
| X open, Y call, Z squeeze, X call (Y folds) | Z's `raise` of `squeeze - Z vs X open Y call`; X's `call` of `vs squeeze - X open vs Z squeeze (Y called)` |
| X open, Y call, Z squeeze, Y call (X folds) | Z's `raise`; Y's `call` of `vs squeeze - Y call vs Z squeeze (X opened)` |

Ranges are absolute (parent × share), as the pack already computes. OOP/IP by postflop order SB, BB, UTG, HJ, CO, BTN. Sizes from `sizes.txt` (open 2.5, SB 3.5; 3-bet/4-bet/squeeze as noted). Pot = what each player put in + dead blinds (SB 0.5, BB 1 when not in the hand) + a folded opener's or caller's amount; stack = 100 − the amount the two remaining players put in. Units ×10; rake 5 / 150. Line text like `BTN 2.5 · BB 13.5 · BTN call`; squeeze `UTG 2.5 · HJ call · BTN 11 · HJ call`. The SB limp is left out.
