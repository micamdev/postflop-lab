# Node lock (première version) : plan d'exécution

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** verrouiller toute la stratégie d'un nœud joueur (mains modifiées à des fréquences choisies, autres mains figées à leur stratégie actuelle), puis re-résoudre la solution avec ses verrous.

**Architecture :** un module Rust `locks` capture un verrou depuis la solution affichée, reconstruit un arbre identique non résolu et y pose les verrous ; des commandes Tauri préparent la re-résolution (vérification avant de libérer la référence) ; le front réutilise la boucle de résolution de Run Solver. Deux PR : cœur Rust (Tasks 1-3), puis éditeur (Tasks 4-5).

**Tech Stack :** Rust (moteur, app Tauri 2), Vue 3 + Pinia.

**Spec :** `docs/superpowers/specs/2026-11-16-node-lock-design.md`

## Global Constraints

- Branche `feat/node-lock` (existe, avec le design). PR 1 (Tasks 1-3) puis PR 2 (Tasks 4-5), vers `dev`. Commits sans `Co-Authored-By`. Vérification puis commit **chaînés** (`&&`).
- Zéro warning : clippy `-D warnings` all features, `pnpm lint`.
- **Un verrou fige tout le nœud** : tableau `actions × mains` complet passé à `lock_current_strategy` (mains modifiées = valeurs saisies, autres = stratégie de la solution de référence).
- Nœuds verrouillables : nœuds joueur de la partie principale, historique sans carte « passée » (`-1`), dans la profondeur sauvegardée. Pas dans une river recalculée (sous-jeu), pas avec le bunching, pas pendant une résolution (en cours ou en pause).
- Re-résolution depuis la **config exacte de la partie** (card_config, tree_config, lignes ajoutées/retirées), jamais depuis la config éditable du front. Tous les verrous sont vérifiés **avant** de libérer la solution de référence.
- Turns symétriques : un verrou posé sous une turn « miroir » est identifié par la turn représentante ; deux verrous visant le même nœud moteur n'en font qu'un (le dernier remplace).
- Aucune commande ne doit paniquer (issue #14) : toutes les entrées venant du front sont validées.
- Métadonnées : schéma v2 = v1 + `locks: Vec<NodeLock>` (`#[serde(default)]`), fichiers v1 toujours lisibles.

## Review Focus

1. **Nœud ou mains décalés** : le verrou rechargé ou réappliqué après reconstruction vise exactement le même nœud et les mêmes mains (indices de mains, turns échangées). Couvert en Task 2 (`full_node_lock_is_exact`, `symmetric_turns_share_one_lock`).
2. **Référence perdue** : un verrou invalide ne libère jamais la solution affichée. Couvert en Task 3 (`invalid_lock_keeps_reference`).
3. **Effet attendu** : réduire le check-raise d'OOP face au c-bet fait monter le c-bet d'IP. Couvert en Task 2 (`less_check_raise_more_cbet`).
4. **Verrous perdus à la sauvegarde** : sauvegarder puis recharger restitue la liste et la stratégie verrouillée. Couvert en Task 3 (`locks_survive_save_and_load`).
5. **Entrées invalides du front** (fréquences négatives, somme ≠ 1, combo inconnu, mauvais nombre d'actions) : erreur claire, pas de panique. Couvert en Task 2 (`invalid_edits_are_errors`).

### Task 2 : module `locks` (pur, testable)

**Files :** Create `desktop/src-tauri/src/locks.rs` (+ `mod locks;`).

**Interfaces :**
- Consumes : `turn_representative` (Task 1), `apply_history_checked`, `actions` (solver.rs).
- Produces :
  - `#[derive(Serialize, Deserialize, Clone, Debug, PartialEq)] pub struct NodeLock { pub history: Vec<usize>, pub player: String /* "oop"|"ip" */, pub actions: Vec<String>, pub hands: BTreeMap<String /* combo, format holes_to_strings */, Vec<f32>>, pub edited: Vec<String> /* combos saisis par l'utilisateur, pour l'affichage */ }`
  - `pub fn canonical_history(game: &mut PostFlopGame, history: &[usize]) -> Result<Vec<usize>, String>` — remplace la carte de turn par sa représentante.
  - `pub fn capture_lock(game: &mut PostFlopGame, history: &[usize], edits: &BTreeMap<String, Vec<f32>>) -> Result<NodeLock, String>` — sur la solution résolue : stratégie complète du nœud (`strategy()`), mains de `edits` remplacées ; valide (combos présents au nœud, une valeur par action, valeurs ≥ 0, somme 1 à 1e-3 près) ; historique canonique ; laisse la partie à sa position.
  - `pub fn rebuild_unsolved(game: &PostFlopGame) -> Result<PostFlopGame, String>` — `ActionTree::new(tree_config)`, `add_line`/`remove_line` des lignes de la partie, `PostFlopGame::with_config(card_config, tree)` (non alloué).
  - `pub fn apply_locks(game: &mut PostFlopGame, locks: &[NodeLock]) -> Result<(), String>` — partie allouée non résolue ; pour chaque verrou : position (`apply_history_checked`), nœud joueur du bon joueur avec les mêmes actions, tableau `actions × mains` dans l'ordre des mains du nœud, `lock_current_strategy` ; retour à la racine.
  - `pub fn merge_lock(locks: &mut Vec<NodeLock>, lock: NodeLock)` — remplace le verrou de même historique canonique.

- [ ] **Step 1 : tests en échec** (petit spot turn ou flop résolu en quelques dizaines d'itérations) : `full_node_lock_is_exact` (capture avec une main modifiée, reconstruction, allocation, `apply_locks`, résolution → au nœud, toutes les mains ont exactement la stratégie verrouillée à 1e-4) ; `symmetric_turns_share_one_lock` (verrous sous deux turns miroirs → même `history` canonique, `merge_lock` n'en garde qu'un) ; `less_check_raise_more_cbet` (verrouiller une part significative de la range OOP face au c-bet sans raise → fréquence de c-bet d'IP à la racine strictement plus haute qu'avant) ; `invalid_edits_are_errors` (combo inconnu, somme ≠ 1, mauvais nombre d'actions, valeur négative → `Err`) ; `lock_on_missing_node_is_error` (historique invalide → `Err`, pas de panique).
- [ ] **Step 2 :** `cargo test -p postflop-lab locks::` → FAIL.
- [ ] **Step 3 :** implémenter.
- [ ] **Step 4 :** `cargo test --release -p postflop-lab` → PASS ; clippy `-D warnings` → PASS (autorisation temporaire `dead_code` si nécessaire, retirée en Task 3).

### Task 3 : commandes, re-résolution, sauvegarde

**Files :** Modify `desktop/src-tauri/src/solver.rs` (ou nouveau `lock_commands.rs`), `main.rs`, `library.rs` (`SolutionMeta.locks`, `META_SCHEMA = 2`), `library_commands.rs` (save/load des verrous).

**Interfaces :**
- Produces (commandes) :
  - `game_capture_lock(history: Vec<usize>, edits: BTreeMap<String, Vec<f32>>) -> Result<NodeLock, String>` — refuse si sous-jeu actif, bunching, partie non résolue.
  - `game_prepare_lock_solve(locks: Vec<NodeLock>, compression: bool) -> Result<(), String>` — construit et alloue l'arbre reconstruit, pose les verrous ; **seulement si tout réussit**, remplace la partie courante et vide le cache des sous-jeux. Mémoire vérifiée comme pour Build Tree.

- Le front relance ensuite la boucle habituelle (`game_solve_step` / `game_exploitability` / `game_finalize`) sans réallouer.
